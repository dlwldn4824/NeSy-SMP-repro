# 연결 명세(grounding spec) — 형식 정의와 소규모 시험

작성 2026-09-17 · 질문: **KG 개념·규칙을 "환자 데이터에서 실행되는 조건"으로 옮기는 단계를 자동 추출할 수 있는가?**
(AnyBURL 은 개념 사이 관계만 다루고, 변수·연산자·임계값·시간·집계·결측은 다루지 않는다 → `KG_RULE_MINING_CHECK.md`)

## 1. 명세 형식 (v0.1)

파일: `NeSy-SMP/configs/grounding_spec_schema.json`

| 칸 | 값 | 예 (원저자 KG 의 젖산) |
|---|---|---|
| concept | KG 개념 | Lactate |
| statement_type | 위험 조건 / 진단 기준 / 치료 목표 / 연결 불가 | risk_condition |
| variable | 변수 카탈로그 이름 | Lactate |
| operator · threshold · unit | `< <= > >= == between present` · 숫자 또는 [하한, 상한] · 단위 | `>=` · 4 · (없음) |
| time_window | 기준 시점 · 시작/끝 시간 | (없음) |
| aggregation | any · all · max · min · mean · latest · 추세 | (없음) |
| combine | n 개 중 m 개 이상 (예: qSOFA 3개 중 2개) | — |
| missing_policy | unknown / false / true | (없음) |
| consequent | 결과 개념 | increasesRiskOf Death |
| provenance | 칸마다 **source(원문) / catalog(변수표) / unspecified(원문에 없음)** | 연산자·임계값 = source |
| evidence | 원문 그대로 | `g.add((SNOMED.Lactate, SCHEMA.greaterOrEqual, Literal(4, ...)))` |

**핵심 원칙 — 추출과 기본값을 나눈다.**
- 추출은 원문에 있는 것만 채우고, 없는 칸은 비워 두고 `unspecified` 로 표시한다.
- 비운 칸은 **컴파일 단계**에서 정해진 기본값으로 채운다: 관찰 창 전체 · `any` · 결측은 `unknown`(측정 없으면 참/거짓 어디에도 안 넣음).
- 그래서 "원문이 정한 것"과 "구현자가 정한 것"이 명세에 기록으로 남는다.

## 2. 시험 설계

| 조각 | 원문 | 시험하려는 것 |
|---|---|---|
| Q | SSC 2021 권고 2 — qSOFA 변수 3개 | 연산자·단위 · "3개 중 2개 동시" 조합 |
| L | SSC 2021 권고 3 — 젖산 | 기준이 **범위(1.6~2.5)**뿐일 때 하나를 지어내지 않는가 · 결과가 사망이 아니라 **패혈증 진단**인 것 |
| M | SSC 2021 권고 9 — 평균동맥압 | **치료 목표(65)**를 위험 조건으로 바꾸지 않는가 · "약 60 미만 → 장기 관류 저하" |
| K | 원저자 KG `create_ckg.py` 트리플 | 임계값 7개 · 동반질환 6개 · 임계값 없는 개념은 "연결 불가"로 두는가 |

- 정답: **추출 실행 전에** 원문 글자 그대로 작성 (`tools/grounding_gold.json`) — 필수 20개 + 선택 6개
- 추출: 조각마다 **대화 기록 없는 새 에이전트**, 프롬프트 파일 1개만 읽음 · 조각 4 × 2회 = 8회
- 채점: 칸 단위 자동 비교 + evidence 가 원문에 그대로 있는지 (`tools/grounding_score.py`)
- 실행: 뽑힌 명세를 6h 학습 입력(26,224 입원)에 그대로 적용 (`tools/grounding_compile.py`)

## 3. 결과 — 추출

| | 1회차 | 2회차 |
|---|---:|---:|
| 필수 20개 찾음 | 20/20 | 20/20 |
| 변수 · 연산자 · 임계값 · 단위 · 문장 유형 | 모두 20/20 | 모두 20/20 |
| 원문에 없는 집계·시간 창·결측 처리를 **지어내지 않음** | 20/20 | 20/20 |
| evidence 원문 그대로 | 20/20 | 20/20 |
| qSOFA "3개 중 2개" 조합 | 3/3 | 3/3 |
| 선택 6개 (연결 불가 개념 등) | 6/6 | 6/6 |
| 반복 일치 (변수·연산자·임계값·결과) | Jaccard **0.92** (35/38) | |

- 함정 3개 모두 통과: 젖산 기준 범위를 `[1.6, 2.5]` 로 그대로 둠 · MAP 65 를 **치료 목표**로 분류 · KG 의 나이 ≥ 65 결과를 **Sepsis 그대로** 둠 (코드는 Death).
- 정답에 없던 추가 명세는 전부 원문 근거가 있음: qSOFA 의 "ICU 재원 연장" 결과 · KG 동반질환의 Sepsis 쪽 트리플 · "이전 가이드라인은 MAP > 65 목표" (2회차).
- 두 회차 차이: "elevated lactate 는 패혈성 쇼크 정의의 일부" 문장에서 1회차만 연산자 `>` 를 채움(수치는 비움) — 원문의 "elevated" 를 연산자로 옮긴 해석 차이.

|---|---:|---:|---|---|---:|

| 동반질환 flag 6개 | 0.5~4.5 | — | HIV 13.4 · 신장질환 14.6 (전체 15.0 보다 낮음) | 9개 중 하나 | 18.3 |

(코드 참%는 결측 제외로 계산한 "기대" 값 — 실제 코드는 0 채우기 때문에 다르다, `REPRO_AUDIT_TABLES.md` §2)

- 명세는 **변환 없이 바로 실행된다.** 수치 조건 모두 위험군 사망률이 나머지보다 높다(젖산 64.5 vs 12.2 등).
- **KG → 코드 사이에서 원저자가 바꾼 것**이 명세 비교로 드러난다:
  - 연산자: 젖산·백혈구·나이 `≥` → `>` · 혈소판 `≤` → `<`
  - 집계: 혈소판만 `all`(모든 시점) — KG 에는 집계가 없음
  - 결과: 나이 KG 는 Sepsis 위험, 코드는 사망 위험
  - 코드에만 있는 조건: GCS < 8 · 호흡수 · 수축기혈압 · 크레아티닌 (KG·SSC 에 수치 없음)
- **SSC qSOFA 기준을 관찰 창 `any` 로 한 개씩 쓰면 너무 넓다:** 호흡수 ≥ 22 한 번이라도 = 89.3%, GCS < 15 = 72.6%. 원문은 "**동시에** 2개 이상"이다 → §4-1.

### 4-1. combine 실행 — qSOFA "3개 중 2개 이상 동시" (6h)

'동시'의 시간 폭은 원문에 없어 세 가지로 계산했다 (컴파일 기본값 후보).
시각마다: 참 개수 ≥ 2 → 참 · 참 + 모름 < 2 → 거짓 · 나머지 모름 (아직 측정 안 된 변수 = 모름). 입원: 한 시각이라도 참 → 참.

| '동시' 기준 | 참% | 모름% | 거짓% | 사망률 참 / 거짓 |
|---|---:|---:|---:|---|
| 같은 시각 (타임스탬프 일치) | 62.3 | **37.7** | 0.0 (수 명) | 20.3 / — |
| 직전 값 1시간 유효 | 75.6 | 22.5 | 1.9 | 18.1 / 6.0 |
| 직전 값 계속 유효 (LOCF) | 79.6 | 12.7 | 7.7 | 17.8 / 3.3 |

입원별 **최대 동시 충족 개수**와 사망률 (전체 15.0%):

| '동시' 기준 | 0개 | 1개 | 2개 | 3개 |
|---|---|---|---|---|
| 같은 시각 | 0.9% · 4.7% | 36.8% · 6.4% | 53.2% · 15.9% | 9.1% · **45.6%** |
| 1시간 유효 | 0.9% · 4.7% | 23.5% · 5.4% | 57.4% · 12.4% | 18.2% · **36.2%** |
| LOCF | 0.9% · 4.7% | 19.5% · 4.5% | 54.4% · 10.9% | 25.2% · **32.6%** |

- 조합으로 좁혀도 **입원의 62~80%가 qSOFA 양성**이다. ICU 패혈증 코호트이고 관찰 창 전체에서 "한 번이라도"를 보기 때문이다. 양성/음성의 사망률 차이는 크다(1h 유효: 18.1 vs 6.0).
- **3개 모두 동시 충족**이 가장 뚜렷한 위험군이다 (같은 시각 45.6% 사망).
- **'동시'를 어떻게 정하느냐에 따라 결과가 크게 달라진다:** 같은 시각이면 GCS 측정이 드물어 37.7%가 '모름'이고, LOCF 면 모름은 12.7%로 줄지만 오래된 값이 섞여 3개 충족군 사망률이 45.6 → 32.6%로 희석된다.
  → 이 폭도 원문에 없는 칸이다. 명세에 `simultaneous_tolerance` 같은 칸을 두고 provenance 를 남겨야 한다.
- 비교: 원저자 코드의 호흡수·수축기혈압 조건은 조합이 아니라 "호흡수(모든 시점) **그리고** 수축기혈압(한 번이라도)"이고 기준도 29/9 · 100 이라 qSOFA 와 다르다.

## 5. 해석

1. **원문에 적힌 수치 조건은 자동으로 명세화할 수 있다.** 작은 시험이지만 변수·연산자·임계값·단위·결과를 모두 맞췄고, 범위만 있는 기준이나 치료 목표를 위험 조건으로 바꾸는 흔한 오류를 피했다.
2. **정작 학습 동작을 좌우하는 칸은 원문에 없다.** 네 조각 모두 시간 창·집계·결측 처리를 말하지 않는다. 원 코드의 문제(0 채우기 → GCS·수축기혈압 전원 켜짐, 크레아티닌 `all` → 절대 안 켜짐)가 전부 이 칸에서 생겼다. → 이 칸은 추출이 아니라 **명시적 기본값 + provenance 기록**으로 다뤄야 한다.
3. **결측이 크다:** 젖산 60% · 빌리루빈 66% · CRP 99% 입원이 관찰 창에 측정이 없다. `unknown` 을 쓰지 않으면 이 입원들이 규칙의 "거짓" 쪽으로 들어간다.

## 한계
- 조각 4개 · 필수 정답 20개 · 조각당 2회 — 쉬운 문장 위주라 만점이 일반화되지 않는다.
- 정답은 이 세션이 원문에서 직접 작성 (판정자 1명). 수치가 원문에 글자로 있어 판단 여지는 적다.
- `time_window` 실행 · 단위 변환은 컴파일러에 아직 없다. `combine` 은 구현했지만 '동시' 허용 폭은 명세 칸이 아니라 실행 옵션으로만 비교했다.
- PADIS 는 로컬 원문 텍스트의 기호(≥, ≤ 등)가 깨져 있어 이번 시험에서 뺐다.
