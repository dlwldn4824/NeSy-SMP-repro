# NeSy-SMP 재현 보고 (2026-09-21)

대상 논문: De Santis 외, *Neuro-symbolic artificial intelligence for real-time sepsis mortality prediction*, Engineering Applications of AI 177 (2026) 114920
기간: 09-15 ~ 09-21 · 데이터: MIMIC-IV (로컬 DB, 논문은 v2.2) · 코드: 원저자 공개 저장소 (commit e7ee0ab)

---

## 한 줄 요약

논문 조건대로 4개 예측 시점(6·12·24·48시간)을 모두 재현했다.
**모든 모델이 논문보다 AUC 가 3~5점 높지만, 논문의 핵심 주장인 "지식 규칙을 넣은 NeSy-SMP 가 가장 좋다"는 네 시점 모두에서 재현되지 않았다.**
원인을 나누어 확인한 결과: ① 공개 코드는 그대로 돌아가지 않고 ② 학습에 쓰이는 규칙 절반이 의도대로 작동하지 않으며 ③ 입력 데이터의 기록 오류가 딥러닝 성능을 1~2점 깎고 있었다. 다만 ②를 고쳐도 성능은 그대로였고, ③을 고치면 모든 딥러닝이 같이 올라 순위는 바뀌지 않았다.

## 1. 재현 결과 — 논문 Table 1 과 비교

AUC (5-fold 평균). 괄호는 논문 값.

| 예측 시점 | XGBoost | RF | BiLSTM | LTN (규칙 없음) | **NeSy-SMP (규칙 있음)** |
|---|---|---|---|---|---|
| 6h | **92.67** (88.56) | 91.18 (88.11) | 89.71 (85.35) | 91.27 (88.10) | 91.02 (**88.33**) |

| 24h | **90.59** (85.35) | 89.20 (85.13) | 85.93 (81.48) | 88.49 (83.91) | 88.80 (**84.58**) |
| 48h | **87.66** (82.34) | 86.77 (**82.65**) | 84.55 (79.15) | 86.24 (80.57) | 86.22 (80.62) |

F1 (5-fold 평균)

| 예측 시점 | XGBoost | RF | BiLSTM | LTN | **NeSy-SMP** |
|---|---|---|---|---|---|
| 6h | 81.72 | 76.75 | 80.62 | **81.74** | 81.66 |
| 12h | **80.41** | 74.31 | 77.58 | 79.64 | 79.73 |
| 24h | 78.16 | 70.22 | 75.77 | 77.38 | 77.96 |
| 48h | 72.55 | 62.96 | 70.23 | **73.66** | 73.33 |

**읽는 법**
1. **모든 모델이 논문보다 높다** (AUC +3~5점). 우리 코호트의 사망률이 15.0% 로 논문(18%)보다 낮아 쉬운 문제가 된 영향이 있다.
2. **네 시점 모두 XGBoost 가 AUC 1등.** 논문에서는 NeSy-SMP 가 1등이었다.
3. **규칙을 넣은 효과가 없다.** NeSy-SMP − LTN 차이는 6h −0.25 · 12h +0.14 · 24h +0.31 · 48h −0.02 로, 같은 코드를 두 번 돌렸을 때 생기는 차이(±0.1~0.3)와 같은 크기다. 논문의 차이는 +0.23 ~ +1.14 였다.
4. 예측 시점이 멀어질수록 성능이 내려가는 경향은 논문과 같다.

## 2. 재현 과정에서 찾은 문제 3가지

### ① 공개 코드는 그대로 실행되지 않는다

| 고친 곳 | 문제 |
|---|---|
| RF·XGBoost 입력 계산 순서 | **첫 fold 에서 오류로 멈춘다.** 평균을 먼저 구해 놓고 그 평균값 리스트로 표준편차를 구하려 한다 |
| 약물 항목 출력 | 논문 변수 목록에 약물이 없는데, 없으면 KeyError 로 멈춘다 |
| 규칙 모델 입력 크기 | 예측 시점마다 사람이 숫자를 바꿔 넣게 돼 있다 |

→ **공개된 코드로는 논문 결과를 만들 수 없다.** 저자가 실제로 쓴 코드는 공개본과 달랐다는 뜻이다. (다른 2건은 입력 경로·fold 별 기록 저장으로, 계산과 무관)

### ② 학습에 쓰이는 규칙 13개 중 6개가 의도대로 작동하지 않는다

원인은 **측정이 없는 칸을 0 으로 채운 뒤 그 0 을 실제 값처럼 비교**하는 것이다.

| 규칙 | 논리대로면 | 실제 코드 |
|---|---:|---:|
| 의식 저하 (GCS < 8) | 27.3% | **100%** (전원 켜짐) |
| 수축기혈압 ≤ 100 | 70.9% | **100%** (전원 켜짐) |
| 크레아티닌 ≥ 1.5 | 27.1% | **0%** (절대 안 켜짐) |
| 혈소판 < 50 | 3.7% | 9.1% |
| 호흡수 이상 · CRP ≥ 100 | 0.2% · 0.5% | 데이터상 해당자가 거의 없음 |
| 혈당 > 100 | 79.8% | **0%** — 코드 버그로 아예 적용 안 됨 |

가장 큰 손실은 GCS 다. 실제로는 사망률 34.5% 인 고위험군 27% 를 가려내야 하는데 전원에게 켜져 정보가 사라진다.

### ③ 입력 데이터에 기록 오류가 있다

수축기혈압 119,119 · 체온 537°C 같은 값. 전체 417만 건 중 3,615건(0.09%)이지만, 딥러닝은 변수별로 최솟값~최댓값 범위에 맞춰 넣기 때문에 **최댓값 하나가 나머지 값을 모두 0 근처로 눌러 버린다.**

## 3. 원인 분리 실험 (6h 기준)

문제 ②·③ 이 성능 차이의 원인인지 각각 따로 확인했다. 비교 기준으로 **같은 원본 코드를 한 번 더 돌려 실행 간 편차**도 측정했다 (원본 코드는 torch 시드를 고정하지 않는다).

| AUC | 원본 1회차 | 원본 2회차 | ② 수정 (missing-aware) | ③ 수정 (극단값 제거) |
|---|---:|---:|---:|---:|
| XGBoost | 92.67 | 92.67 | 92.67 | 92.85 |
| RF | 91.18 | 91.18 | 91.18 | 91.38 |
| BiLSTM | 89.71 | 90.00 | 90.33 | **91.56** |
| LTN | 91.27 | 91.21 | 91.23 | **92.27** |
| **NeSy-SMP** | 91.02 | 91.14 | 91.17 | **92.27** |

### ② 규칙 판정을 고쳐도 성능은 그대로

- 패치 후 규칙 켜짐 비율은 의도한 값과 정확히 일치한다 (GCS 27.2% · 혈압 71.0% · 크레아티닌 27.1% · 혈소판 3.7%).
- 그런데 NeSy-SMP 는 +0.03 (재실행 대비). **사실상 0.**
- **이유를 코드에서 확인했다:** 잘못 켜지던 GCS·혈압·크레아티닌·호흡수 규칙은 "위험하면 사망" 함축 공리에 연결돼 있지 않다. 각 규칙에 붙은 작은 판정기만 학습시키고 **최종 사망 예측으로 가는 경로가 없다.** 그래서 맞게 켜지든 틀리게 켜지든 결과가 같다.

### ③ 극단값을 지우면 딥러닝만 1~2점 오른다

- BiLSTM +1.6~1.9 · LTN +1.0 · NeSy-SMP +1.1~1.3 (실행 편차 ±0.1~0.3 보다 큼) · 트리 모델은 +0.2.
- XGBoost 와 NeSy-SMP 의 AUC 차이가 1.6 → **0.6** 으로 줄었다. F1 은 순위가 바뀌어 LTN 82.80 · NeSy-SMP 82.79 > XGBoost 81.81.
- 하지만 **NeSy-SMP 와 LTN 은 여전히 동일** (92.27 = 92.27). 향상은 규칙이 아니라 **데이터 정제**에서 왔다.

### 규칙 만족도 (knowledge satisfaction) — 처음 측정

원저자 코드는 이 값을 출력하지 않아, 계산값을 읽어 기록만 하는 패치를 넣었다.

| | 원본 | ② 수정 | ③ 수정 |
|---|---:|---:|---:|
| data 공리 | 0.609 | 0.609 | 0.620 |
| knowledge 공리 | 0.791 | 0.796 | 0.788 |

- **앵커 공리(수치가 기준을 넘으면 "위험"이라고 표시)는 거의 1.0** — 쉽게 만족된다.
- **함축 공리(위험하면 사망)가 낮다:** 나이 0.61 · 만성질환 0.76 · 빌리루빈 0.78. 고령·만성질환 환자 대부분이 실제로 생존하므로 이 공리는 데이터와 충돌한다.
- 즉 지식 공리는 성능을 돕는 방향이 아니라 **데이터와 반대 방향으로 약한 압력**을 준다 (가중치 0.2).

## 4. 지식 파이프라인 감사 — "가이드라인 → KG → 규칙 → 공리"가 실제로 작동하는가

논문은 가이드라인에서 지식그래프를 만들고 규칙을 자동 채굴해 논리 공리로 옮긴다고 설명한다. 각 단계를 직접 실행해 확인했다.

| 단계 | 확인한 것 | 결과 |
|---|---|---|
| 규칙 채굴 (AnyBURL) | 원저자 KG 로 저자 설정 그대로 채굴·필터 | 통과한 규칙은 "위험인자면 사망 위험 증가" 같은 **일반형뿐**. 구체적 임계값 규칙 0개 |
| 공리 임계값 출처 | 논문·KG·SSC 2021·다른 중증도 점수와 대조 | 논문에 숫자로 적힌 건 젖산 4.0 하나. 코드에만 있는 값은 **qSOFA·MEWS·SOFA·APACHE II·SSC 2012** 와 겹친다. CRP 100 · 백혈구 30 · 혈당 100 은 어느 출처와도 맞지 않음 |
| 개념 → 실행 조건 연결 | 연결 명세 형식을 정의하고 소규모 자동 추출 시험 | 원문에 **수치로 적힌 조건은 20/20 정확 추출**. 그러나 시간 창·집계 방식·결측 처리는 **어느 원문에도 없다** — 문제 ②가 생긴 칸이 바로 여기다 |
| 규칙 추출 재현 (sepsis) | SSC 2021 원문에서 기존 규칙 재추출 (예시 0·1·11개 비교) | 확인용 19개 중 **1개만** 원문에서 나온다. SSC 는 치료 가이드라인이라 "동반질환 → 사망" 같은 규칙의 근거가 본문에 없다 |
| 규칙 추출 재현 (PADIS·섬망) | 2018 PADIS 원문으로 같은 실험 | 확인용 14개 중 **10개** 재현. PADIS 는 위험인자를 문장으로 명시하기 때문. 예시는 새 규칙을 찾게 하는 게 아니라 **표현을 정답 형식으로 맞추게** 한다 |

**결론:** 공개 코드 기준으로 이 파이프라인은 자동이 아니다. **KG 를 사람이 손으로 쓰고, 임계값도 사람이 정해 코드로 옮긴** 구조다. 채굴 단계는 학습 공리와 이어져 있지 않다.

## 5. 코호트 — 논문과 다른 점

| 단계 | 남은 ICU 입원 | 사망률 |
|---|---:|---:|
| MIMIC-IV ICU 전체 | 94,458 | 12.0% |
| 감염 의심 | 53,297 | 15.9% |
| Sepsis-3 (SOFA ≥ 2) | 41,296 | 18.1% |
| 2008–2019 | 35,808 | 16.9% |
| ICU 재원 ≥ 24h | 32,148 | 16.7% |
| 입원 중 ICU 1회 | **26,251** | **15.1%** |
| (논문) | 19,328 | 18% |

- 논문 제외 기준 중 **"분석에 필요한 데이터가 없는 환자 제외"에 구체적 정의가 없다.**
- 여러 해석을 시도했지만 19,328명·18% 를 동시에 맞추는 조합은 없었다. 사망률 18% 는 "ICU 1회"를 환자 단위로 읽을 때만 나오고(18.4%), 그때 인원은 15,640명이다.
- **논문 숫자에 맞추려고 기준을 바꾸지 않았다.**

## 6. 정리 — 논문 주장별 재현 여부

| 논문의 주장 | 재현 결과 |
|---|---|
| 5개 모델 중 NeSy-SMP 가 가장 좋다 | ❌ 네 시점 모두 XGBoost 가 AUC 1등 |
| 지식 규칙을 넣으면 성능이 오른다 (NeSy > LTN) | ❌ 차이가 실행 간 편차 수준 (±0.3) |
| 가이드라인 → KG → 자동 규칙 채굴 → 공리 | ❌ 채굴 결과는 공리와 무관. KG·임계값 모두 수작업 |
| 예측 시점이 멀어지면 성능 하락 | ✅ 동일한 경향 |
| 절대 성능 수준 | ⚠️ 모든 모델이 논문보다 3~5점 높음 (코호트·데이터 버전 차이) |

## 7. 남은 일

1. 극단값 제거 조건에서 12·24·48h 도 돌려 "데이터 정제 효과"가 시점 전반에 유지되는지 확인
2. 논문 저자에게 문의할 항목 정리: 제외 기준 정의 · 공리 임계값 출처 · 공개 코드와 실제 코드 차이
3. PADIS 지식그래프 사람 검토 시 확인할 항목: "섬망 → 사망"은 2018 원문이 뒷받침하지 않음 · 위험인자 대부분은 원문이 "연관" 수준으로만 진술

## 한계

- 데이터 버전이 다르다 (논문 v2.2 / 우리 로컬 DB 는 2022년까지 포함 → 연도로 잘라 근사).
- 원본 코드가 torch 시드를 고정하지 않아 딥러닝 계열은 실행마다 ±0.1~0.3 흔들린다 (그대로 유지).
- 생존자의 관찰 구간은 원본이 무작위 선택인데, 우리는 재현을 위해 고정했다.
- 규칙 만족도는 학습 배치 기준이다 (시험 fold 값은 원본 코드가 필요한 가중치를 저장하지 않아 계산 불가).
- 규칙 추출·연결 명세 실험의 판정자는 LLM 이고, 확인용 규칙 수가 14~20개로 작다.
