# 원 논문 KG → 규칙 채굴 → 공리 점검 (AnyBURL)

작성 2026-09-17 · 질문: **학습 코드에 적힌 NeSy 공리가 원저자의 KG·규칙 채굴 과정에서 나오는가?**

## 방법

| 단계 | 원저자 코드 | 실행한 것 |
|---|---|---|
| ① KG 만들기 | `create_ckg.py` — 사람이 손으로 적은 RDF 트리플 | 그대로 실행 (그림 그리는 `pyvis` 만 대체) → **90 트리플** |
| (채굴 입력) | `extract_rules.py` 가 읽는 `rules/pkg.txt` | repo 에 있던 파일 그대로 → **82 트리플** (①과 거의 같은 KG, 네임스페이스 제거·임계값 없음) |
| ② 규칙 채굴 | PyClause 로 AnyBURL 실행 (학습 30초, 스레드 2, 순환 규칙 길이 5) | **AnyBURL 공식 jar (23-1x) 로 같은 설정** — PyClause 는 PyPI 에 없고 Windows 빌드 불가 |
| ③ 필터 | `filter_rules.py` — 신뢰도 ≥ 0.8 · domain/range 제외 · 규칙 머리가 Death/Outcome | 같은 조건 |
| ④ 규칙 → 공리 | **코드 없음** | ③ 결과와 `stratified_main.py` 공리를 비교 |

결과 파일: `NeSy-SMP/rules/anyburl_run/`

## 결과

### ②③ 채굴·필터
| 입력 | 채굴된 규칙 | 필터 후 |
|---|---:|---:|
| `pkg.txt` (82) | 1,374 | **27** |
| `create_ckg.py` KG (90) | 277 | **14** |

**필터를 통과한 규칙은 전부 변수(X)만 쓰는 일반 규칙이다.** 구체적 검사·임계값이 나오는 규칙은 0개. 대표:
```
increaseRiskOf(X,Death) <= rdf-schema#subClassOf(X,RiskFactor)    conf 0.94   (위험인자면 사망 위험 증가)
increaseRiskOf(X,Death) <= rdf-schema#subClassOf(X,Comorbidity)   conf 1.00   (동반질환이면 사망 위험 증가)
increaseRiskOf(X,Death) <= increasesRiskOf(X,Sepsis)               conf 1.00
increasesRiskOf(X,Death) <= increaseRiskOf(X,Death)                conf 1.00   ← 술어 오타 두 개가 서로를 설명
```
- 규칙에 나오는 개체는 `RiskFactor · Comorbidity · Sepsis · Death · Outcome · Patient` 뿐.
- `pkg.txt` 규칙의 상당수는 **술어 오타(`increaseRiskOf` / `increasesRiskOf`)가 같은 사실을 두 번 적은 것**을 서로 설명하는 규칙이다.

## 결론

1. **학습 코드의 공리는 규칙 채굴에서 나오지 않는다.** 원저자 설정 그대로 채굴·필터한 규칙은 "위험인자/동반질환이면 사망 위험 증가" 같은 일반형뿐이고, 구체적 검사·임계값 공리는 하나도 없다.
2. **공리의 임계값은 사람이 손으로 쓴 KG(`create_ckg.py`)에 이미 들어 있다.** 사망 함축 공리 8개 중 6개(젖산·빌리루빈·혈소판·CRP·백혈구·나이)의 임계값이 KG 와 같다. 즉 공리는 채굴이 아니라 **KG 작성 단계에서 사람이 정한 것**을 코드로 옮긴 것으로 보인다.
3. **코드에는 KG 에 없는 조건이 있다.** 젖산 안 떨어짐 · GCS · 호흡수 · 수축기혈압 · 크레아티닌 · 혈당 — KG 에도, 채굴 규칙에도 없다. 반대로 KG 의 평균혈압 ≤ 65 는 코드에서 쓰이지 않는다.
4. 논문이 제시한 "가이드라인 → KG → 규칙 채굴 → FOL 공리" 자동 파이프라인은, 공개 코드 기준으로는 **KG 를 손으로 쓰고 공리를 손으로 옮긴** 구조다. (9/15 추출 점검 결론 "기존 sepsis 규칙 대부분은 SSC 2021 원문에 없다" 와 일관된다.)

한계: PyClause 대신 AnyBURL 공식 jar 사용 (같은 알고리즘·설정, 기본값 일부 차이 가능) · AnyBURL 은 무작위 탐색이라 실행마다 규칙 수가 조금 다를 수 있다 — 필터 후 규칙 **형태**(일반형뿐)는 두 입력 모두 같다.
