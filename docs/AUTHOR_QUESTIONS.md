## 1. "분석에 필요한 데이터가 없는 환자"의 정확한 제외 기준

**배경.** 논문 §5.1 은 코호트를 19,328 ICU 입원 · 사망률 약 18% 로 적고, 제외 기준 중 하나로 "분석에 필요한 데이터가 없는 환자"를 든다. 어떤 변수가 몇 개 이상 있어야 하는지는 적혀 있지 않다.

**우리가 확인한 것** (`docs/LAB_REPORT_2026-09-21.md` §5, `docs/REPRO_AUDIT_TABLES.md`)

| 단계 | 남은 ICU 입원 | 사망률 |
|---|---:|---:|
| MIMIC-IV ICU 전체 | 94,458 | 12.0% |
| 감염 의심 | 53,297 | 15.9% |
| Sepsis-3 (SOFA ≥ 2) | 41,296 | 18.1% |
| 2008–2019 | 35,808 | 16.9% |
| ICU 재원 ≥ 24h | 32,148 | 16.7% |
| 입원 중 ICU 1회 | **26,251** | **15.1%** |
| (논문) | 19,328 | 18% |

- 여러 해석을 시도했지만 19,328명과 18% 를 동시에 맞추는 조합은 찾지 못했다.
- 사망률 18% 는 "ICU 1회"를 **환자 단위**로 읽을 때만 나오고(18.4%), 그때 인원은 15,640명이다.
- 논문 숫자에 맞추려고 기준을 바꾸지는 않았다.

**질문**

1. "필요한 데이터"는 구체적으로 어떤 변수 집합인가? 논문 §5.1 의 21개 변수 전부인가, 일부(예: 젖산·GCS)인가?
2. 그 변수는 **관찰 창(24h) 안에서 최소 몇 회** 측정돼야 하는가? 1회 이상인가, 창 전체 커버리지 조건이 있는가?
3. 집계 단위가 ICU 입원(stay)인가, 입원(hadm)인가, 환자(subject)인가?
4. 제외 단계의 **적용 순서**는? (감염 의심 → Sepsis-3 → 기간 → LOS → ICU 1회 → 데이터 결측 순서인지)
5. MIMIC-IV **v2.2 의 어떤 기간 필터**를 썼는가? (2008–2019 년 anchor_year_group 기준인지)

**왜 필요한가.** 우리 코호트 사망률이 15.0% 로 논문(18%)보다 낮아 문제 자체가 쉬워졌고, 이것이 전 모델 AUC 가 논문보다 3~5점 높은 주된 이유로 보인다. 코호트가 맞지 않으면 나머지 비교가 전부 근사치가 된다.

## 2. 공개 코드와 논문 실험 코드의 차이

**배경.** 공개 저장소 코드를 그대로 실행하면 논문 결과를 만들 수 없다.

**우리가 확인한 것** (`NeSy-SMP/upstream_faithful/PATCHES.md`)

| # | 위치 | 증상 · 내용 |
|---|---|---|
| P5 | `stratified_main.py` RF/XGB 피처 3곳 | 평균으로 바뀐 리스트(float)에 다시 `np.std(lst) for lst in features` → **fold 1 에서 `TypeError: 'float' object is not iterable` 로 중단**. 표준편차를 먼저 계산하도록 순서만 바꿔 실행 |
| P3 | `data/preprocessing.py` | `get_loc("Administration of vasopressor")` — 논문 §5.1 변수 목록에 약물이 없어 범주가 없으면 KeyError. 출력문이라 계산 무관 |
| P4 | `model/models.py` | `MLP.fc1 = Linear(254)` 하드코딩(주석에 lead 별 289/261/275) → 예측 시점마다 사람이 숫자를 고쳐야 함. 우리는 `input_size + 23 + 1` 로 계산 |
| P1·P2 | `stratified_main.py` | 입력 경로 하드코딩 · fold 별 지표 미저장 (계산 무관, 실행 편의) |

또한 학습 공리 중 **혈당 > 100 조건은 활성률 0%** 로, 코드 경로상 한 번도 적용되지 않는다(`docs/SENSITIVITY_MISSING_AWARE.md`).

**질문**

1. 논문 Table 1 을 만든 코드는 공개본 `e7ee0ab` 와 동일한가? 다르다면 **실험에 사용한 커밋/버전**을 공유해 줄 수 있는가?
2. P5 의 표준편차 계산은 원래 "변수별 0 제외 평균과 표준편차"를 의도한 것이 맞는가? 실험 때는 어떤 형태였는가?
3. `MLP.fc1` 의 입력 크기는 예측 시점마다 수동으로 바꿨는가? (6/12/24/48h 각각의 값)
4. 혈당 공리가 실제로 활성화되지 않는 것을 인지하고 있었는가?

**왜 필요한가.** 공개 코드로 재현할 수 없다는 점 자체가 보고해야 할 결과이지만, 실험 코드가 따로 있다면 우리 수정(P5 순서 변경 등)이 원저자 의도와 다를 수 있다.

## 3. 공리 임계값의 출처

**배경.** 논문 §4.3 은 임계값을 "지식그래프에 질의해 체계적으로 얻을 수 있다"고 적는다. 그러나 본문에 숫자로 적힌 임계값은 **젖산 > 4.0 하나**뿐이다.

**우리가 확인한 것** (`docs/AXIOM_THRESHOLD_SOURCES.md`)

- 코드에만 있고 KG·SSC 2021 어디에도 없는 임계값: **GCS < 8 · 수축기혈압 ≤ 100 · 호흡수 ≥ 29 또는 < 9 · 크레아티닌 ≥ 1.5 · 혈당 > 100**.
- 값 대조 결과: 수축기혈압 ≤ 100 은 **qSOFA** 와 일치(공개 `main.py` 도 변수명을 `qSOFA_clinical_concept_values` 로 씀), 호흡수 < 9 는 **MEWS**(코드 주석 `# mews score risk`), 혈소판 < 50 · 빌리루빈 2 는 **SOFA/SSC 2012**, 젖산 4 는 **SSC 2012**, 크레아티닌 1.5 는 **APACHE II** 구간 하한과만 같다.
- **CRP ≥ 100 · 백혈구 > 30 · 혈당 > 100 은 대조한 어떤 가이드라인·점수와도 값이 맞지 않는다.** 두 값은 손으로 쓴 KG 에만 있다.
- 논문 §4.5 의 공리 목록에는 **LowMAP(MAP < 65)** 이 있으나 코드에서는 정의만 되고 쓰이지 않는다. 반대로 GCS·호흡수·수축기혈압·크레아티닌·혈당은 논문 목록에 없다.

**질문**

1. 각 임계값의 출처를 문헌 단위로 알려줄 수 있는가? 특히 **CRP ≥ 100 · 백혈구 > 30 · 혈당 > 100**.
2. "KG 질의로 임계값을 얻는다"는 것은 실제로 실행되는 절차인가, 개념 설명인가? 실행된다면 **질의문**을 공유해 줄 수 있는가?
3. 호흡수 조건(≥ 29 또는 < 9)은 MEWS 의 ≥ 30 / < 9 에서 온 것인가? 경계가 1 다른 이유가 있는가?
4. 논문 목록의 **LowMAP 이 코드에서 빠진 것**과, 코드에만 있는 5개가 **논문 목록에 없는 것**은 의도된 차이인가?

**왜 필요한가.** 임계값은 규칙 활성률을 통해 모델이 받는 지식 신호의 양을 직접 결정한다. 출처가 확정되지 않으면 "가이드라인에서 왔다"는 논문의 핵심 서술을 검증할 수 없다.

## 4. 규칙 채굴 결과가 학습 공리로 연결되는 과정

**배경.** 논문은 가이드라인 → 지식그래프 → (AnyBURL) 규칙 채굴 → FOL 공리 순서의 파이프라인을 제시한다.

**우리가 확인한 것** (`docs/KG_RULE_MINING_CHECK.md`)

- `create_ckg.py` 의 KG 는 사람이 손으로 적은 90개 트리플이고, 채굴 입력 `rules/pkg.txt` 는 82개 트리플(임계값 없음)이다.
- 저자 설정 그대로 채굴·필터(`filter_rules.py`, 신뢰도 ≥ 0.8, 머리 = Death/Outcome)하면 통과 규칙은 27개(pkg) / 14개(ckg)인데 **전부 변수만 쓰는 일반형**이다: 예) `increaseRiskOf(X,Death) <= subClassOf(X,RiskFactor)` conf 0.94.
- **구체적 임계값이 등장하는 규칙은 0개**이고, 채굴 결과를 공리로 옮기는 코드는 저장소에 없다.
- 규칙 상당수는 술어 오타(`increaseRiskOf` / `increasesRiskOf`)로 같은 사실이 두 번 들어가 서로를 설명하는 형태다.

**질문**

1. 채굴된 규칙 중 **어떤 규칙이 어떤 학습 공리로** 옮겨졌는지 대응표를 줄 수 있는가?
2. 그 변환은 자동인가 수작업인가? 자동이라면 해당 스크립트를 공유해 줄 수 있는가?
3. PyClause/AnyBURL 의 **버전과 설정 파일**은 무엇인가? (우리는 PyClause 가 Windows 에서 설치되지 않아 AnyBURL 23-1x jar 로 같은 설정을 사용했다)
4. 술어 오타 두 가지가 KG 에 함께 존재하는 것은 의도인가?

**왜 필요한가.** 이 연결이 없으면 논문의 "자동 파이프라인" 주장이 성립하지 않고, 실질적으로는 사람이 쓴 KG + 사람이 정한 임계값이 된다. 우리 재현에서는 후자로 보인다.

## 5. 지식 손실(knowledge loss)에 포함되는 규칙의 선정 기준

**배경.** 학습 손실은 `1 − (0.8 · data + 0.2 · knowledge)` 형태이고, knowledge 쪽에는 **앵커 공리**(값이 기준을 넘으면 "위험" 술어가 참)와 **함축 공리**(위험하면 사망)가 함께 들어간다.

**우리가 확인한 것** (`upstream_faithful/stratified_main.py` L585~645)

- 함축 공리 `… → P(사망)` 가 있는 개념은 **8개**: 젖산 · 빌리루빈 · 혈소판 · 젖산 미개선 · CRP · 만성질환 · 백혈구 · 나이.
- 앵커만 있고 함축이 없는 개념은 **GCS · 수축기혈압 · 호흡수 · 크레아티닌 · 혈당**. 이들은 작은 판정기만 학습시키고 최종 사망 예측으로 가는 경로가 없다.
- 그래서 측정 결측을 0 으로 채워 GCS·혈압 규칙이 전원에게 켜지고 크레아티닌이 전혀 켜지지 않던 문제를 고쳐도(`docs/SENSITIVITY_MISSING_AWARE.md`) AUC 변화는 +0.03 으로 사실상 0 이었다.
- 논문 §4.5 의 공리 목록 9개와도 구성이 다르다(LowMAP 포함, GCS·호흡수·혈압·크레아티닌·혈당 미포함).

**질문**

1. 함축 공리를 8개 개념에만 붙인 것은 **의도된 설계**인가? 기준이 있었다면 무엇인가?
2. GCS·수축기혈압·호흡수·크레아티닌 앵커 공리는 최종 예측에 어떤 경로로 기여하도록 의도됐는가?
3. `w_knowledge = 0.2` 는 어떻게 정했는가? 탐색 범위와 선택 근거가 있는가?

**왜 필요한가.** 우리 재현에서 NeSy-SMP 와 규칙 없는 LTN 의 차이는 네 시점 모두 실행 간 편차(±0.1~0.3) 수준이었다. 위 구조가 그 이유를 설명하는 유력한 후보다.

## 6. 학습 시 사용한 시드 및 실제 코호트 생성 코드

**배경.** 공개 코드는 torch 시드를 고정하지 않고, 생존자의 관찰 구간 선택이 무작위다.

**우리가 확인한 것**

- 같은 코드를 두 번 돌리면 딥러닝 계열 AUC 가 **±0.1~0.3** 흔들린다(`docs/LAB_REPORT_2026-09-21.md` §3). 논문이 보고한 NeSy-SMP − LTN 차이(+0.23 ~ +1.14)와 겹치는 크기다.
- 우리는 재현성을 위해 생존자 관찰 구간을 고정했고(`make_leadtime_csvs.py --seed 32`), 그 외 학습 시드는 원본 그대로 두었다.
- 저장소에는 코호트 생성 코드(감염 의심·Sepsis-3·제외 기준 적용)가 없다.

**질문**

1. 학습·분할에 사용한 **시드 값**(torch / numpy / 5-fold 분할)은 무엇인가? 고정하지 않았다면 Table 1 은 **몇 회 실행의 결과**인가?
2. 모델 간 차이에 대한 **반복 실행 편차나 유의성 검정**을 수행했는가?
3. 생존자의 24h 관찰 구간은 어떻게 선택했는가(무작위 / 마지막 / 첫 구간)? 무작위라면 시드는?
4. **코호트 생성 코드(또는 SQL)** 를 공유해 줄 수 있는가? 가능하다면 stay_id 목록이 가장 확실하다.

**왜 필요한가.** 시드와 실행 횟수를 모르면 논문의 성능 차이가 방법의 효과인지 실행 편차인지 구분할 수 없다. 코호트 코드는 1번 항목과 함께 재현 격차의 가장 큰 원인을 제거한다.
