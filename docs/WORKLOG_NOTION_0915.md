## 2. 실험 A — 재현: 동반질환 출처별 비교

### 2-1. 질문
우리 재현 결과가 논문보다 AUC 가 3~4 높다. 논문은 퇴원기록 NLP 로 동반질환을 뽑았고, 우리는 처음에 동반질환을 0 으로 뒀다가 ICD 로 채웠다.
→ **동반질환 출처 차이가 격차의 원인인가?**

### 2-2. 설정
세 arm 모두 같다. **동반질환 출처만 다르다.**

```
데이터      events_6h_wide_s3 (6h 창) · n = 18,887 입원 · 사망률 18.6%
학습        reproduce_tables.py · seed 42 · epochs 30 (BiLSTM) / 15 (LTN·NeSy)
평가        5-fold, Table 1 = fold 평균 · Table 2 = OOF bootstrap
모델        RF · XGBoost · BiLSTM · LTN · NeSy-SMP
arm         ① 동반질환 없음(0)  ② ICD 코드 기반  ③ NLP(퇴원기록, 방식 B)
```

- NLP 동반질환 커버리지: **76.6%** (18,896 입원 중 14,465). 나머지 23.4% 는 퇴원기록이 없어 병합 단계의 `fillna(0)` 으로 **'동반질환 없음'** 이 된다.
- 세 arm 의 fold 배정이 같은지 OOF 예측으로 확인 → **입원→fold 100% 일치.** 그래서 fold 별로 짝지어 뺄 수 있다.

### 2-5. 해석

> **① 논문과의 격차는 동반질환 때문이 아니다.**
> 어느 arm 이든 NeSy-SMP 가 논문보다 AUC 3.8~4.2 높다(모델별로는 +3.4~+7.2). 동반질환 효과(최대 0.6)의 6배 이상.
> → 원인은 코호트·전처리·레이블 정의 등 다른 곳에서 찾아야 한다.

- **② ICD 동반질환은 작지만 일관되게 도움** — 모든 모델에서 +0.3~0.6, 4~5/5 fold 양수.

  학습은 여전히 이렇게 섞인 데이터로 했으므로 **"NLP 추출이 나쁘다"로 결론 내리면 안 된다.**

## 4. 실험 C — sepsis 규칙 추출 재검증 (few-shot, held-out)

### 4-1. 질문
회의 결정: "기존 연구 규칙을 few-shot 으로 주고 SSC 가이드라인을 보고 다시 뽑아서 기존 규칙과 비교. 한 번 더 시켰을 때 제대로 나오는지."
→ **원 논문의 sepsis 규칙은 SSC 2021 가이드라인에서 재현 가능하게 추출되는가?**

### 4-2. 기존 방식이 이 질문에 답하지 못하는 이유 (먼저 확인)
- **이전 PADIS few-shot 은 설계부터 오염:** 예시 12개가 **전부** 채점 정답(20개) 안에 있었고, 맞힌 7개 중 5개가 예시였다.
- **regex 추출(실제 SSC 2021 원문, 12개)은 정답 일치율 100% 인데 근거가 맞는 건 2개:** 참고문헌 목록에서 뽑은 것, "사망률이 **비슷했다**"는 문장에서 `→ Death` 를 뽑은 것 등.
  → **정답 일치율은 추출이 맞는지 재지 못한다. 근거 검수가 1차 지표여야 한다.**
- **이 세션(Claude 본 세션)은 정답 규칙을 이미 봤다** → 직접 추출하면 오염. 대화 기록 없는 새 서브에이전트에게 맡겼다.

### 4-3. 설계

| 결함 | 고친 방법 |
|---|---|
| 예시로 보여준 규칙으로 채점 (순환) | 정답 30개를 **예시 11 / 확인용 19** 로 분할(주어 개념 단위, seed 20260915). 프롬프트엔 예시만. **재현율은 확인용에서만** |
| 정답 일치 ≠ 근거 지지 | 모든 추출을 근거 문장과 함께 **Y / 부분 / N 판정.** 주지표 = 근거 지지율, 근거 지지 held-out recall |
| 원문 365KB | 서지·참고문헌 제거 후 **본문 전체**를 최상위 섹션 6조각으로. 키워드로 섹션을 고르지 않음 |
| 판정자가 출처를 알면 편향 | LLM 추출과 regex 추출을 **섞고 출처·정답 여부를 가린 채** 판정, 판정 후 키로 해제 |

**격리 절차**
1. 6조각을 **서로 다른 새 서브에이전트 6개**가 동시에 추출. 리포 경로·평가 사실·정답 규칙을 주지 않았고, 프롬프트는 리포 밖으로 복사해 넘김.
2. 모든 추출 에이전트가 도구를 **정확히 2번**(프롬프트 읽기·결과 쓰기)만 썼다 — 다른 파일을 뒤지지 않았다는 흔적.
3. 같은 절차를 **run2** 로 한 번 더(새 에이전트 6개), 다른 시드로 섞어 **두 번째 판정자**에게.

### 4-4. 결과

| | 추출 | **근거 지지율 (블라인드)** | 확인용 정답 일치 | **근거 지지 held-out recall** |
|---|---:|---:|---:|---:|
| **few-shot LLM** (run1) | 10 (고유 7) | **100%** (Y 10) | 5.3% (1/19) | **5.3%** (1/19) |
| **few-shot LLM** (run2) | 10 (고유 7) | **80%** (Y 8 · 부분 2) | 5.3% | **5.3%** |
| **regex (기존)** | 12 | **8%** (Y 1 · 부분 1 · N 10) | 42.1% (8/19) | **5.3%** (1/19) |

- **LLM 은 뽑은 것이 전부 근거가 있다.** 정답 밖 5개(`Sepsis causedBy Pneumonia`, `Hypotension associatedWith SepticShock`, `Lactate associatedWith Death/Sepsis/SepticShock`)도 근거가 맞았다.
- **regex 의 42.1% 는 가짜 일치다.** 근거가 맞는 것만 세면 두 방식 모두 1/19 (`SepticShock → Death`).
- **재현성:** run1 과 run2 의 조각별 개수(6·1·0·1·0·2)와 고유 트리플 7개가 **완전히 같다 — Jaccard 1.00.** → "한 번 더 시켰을 때" 같게 나온다.
- **판정 신뢰도:** regex 12항목에서 두 판정자 **12/12 일치, Cohen κ = 1.00.** 갈린 건 LLM 추출 2개뿐 — 둘 다 '정의상 구성요소'(젖산·저혈압 ⊂ 패혈성 쇼크 정의)를 연관으로 볼지의 경계 사례.
- **부수 발견:** `Lactate` — 정답은 `increasesRiskOf Death` 인데 원문은 **연관만** 진술. 정답이 원문보다 강하게 적혀 있다.

### 4-5. 결론

> **기존 sepsis 규칙 대부분은 SSC 2021 원문에 쓰여 있지 않다.**
> 원문을 충실히 읽으면 그 규칙들이 나오지 않고(근거 지지 80~100% · 재현 5.3%),
> 단어를 맞추면 무관한 문장에서 나온다(재현 42.1% · 근거 지지 8%).
> → **원 논문 규칙은 가이드라인에서 추출됐다기보다 일반 임상 지식으로 작성된 것으로 보인다.**

**PADIS 에 주는 함의:** LLM 추출은 '가이드라인에 쓰인 것'을 정확히 뽑는다. 원 논문식 규칙 세트(검사값·동반질환 → 사망)는 기대하면 안 되고, 가이드라인 근거가 있는 규칙만 남는다.
PADIS KG 검수에서 23개 중 12개가 원문 근거로 승인된 것과 대조적이다.

### 4-6. 한계
- **판정자도 LLM** (같은 계열). κ 1.00 은 기준 적용이 일관됐다는 뜻이지 사람 판단과 같다는 보장은 아니다 → 사람이 N 판정 10개를 한 번 훑을 것.
- **격리는 지시에 의존.** 도구 2회 사용은 준수의 흔적이지 보장이 아니다. 완전 격리가 필요하면 사람이 웹 LLM 새 세션에 `FEWSHOT_SEPSIS_README.md` 대로 붙여넣어 재확인.
- **확인용 19개** → 트리플 하나가 5.3%p. 두 방식의 '동률'도 1개 대 1개.
- **SSC 2021 은 치료 가이드라인**이라 위험인자 서술 자체가 적다. 결론은 '이 가이드라인에는 없다'이지 'LLM 이 못 찾는다'가 아니다.
