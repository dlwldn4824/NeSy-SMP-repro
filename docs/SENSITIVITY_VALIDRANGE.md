# 민감도 실험 B — 기록 오류 극단값 제거 (6·12·24·48h)

작성 2026-09-19 · 질문: **SBP 119,119 · 체온 537°C 같은 기록 오류 값이 딥러닝 성능을 깎고 XGBoost 우위를 만드는가?**
바꾼 것: 입력 데이터만 — mimic-code 유효 범위를 벗어난 측정값 **3,615건 / 417만 건 (0.09%)** 제거 (`NeSy-SMP/tools/filter_valid_ranges.py`).
코드는 원본 + 기록 패치 P6 (`upstream_faithful_log`), 나머지 조건 동일. 결과 `results_sens_validrange_6h/`

## 해석

1. **0.09% 의 기록 오류가 딥러닝 계열 AUC 를 1~2점 깎고 있었다.** 변화 폭(+1.0~1.9)이 같은 코드 재실행 편차(±0.1~0.3)보다 훨씬 크다. 트리 모델(XGBoost·RF)은 +0.2 로 거의 그대로.
   - 딥러닝 입력은 변수별 MinMax 정규화라, 최댓값 하나(예: 수축기혈압 119,119)가 나머지 값을 0 근처로 눌러 버린다. 트리 모델은 순서만 보므로 영향이 작다.
2. **XGBoost 와의 차이가 줄었다.** AUC 차이 XGBoost − NeSy-SMP: 1.53~1.65 → **0.58**. XGBoost 가 여전히 5 fold 모두 1등 (fold 4·5 는 0.07~0.08 차이).
3. **F1 은 순위가 바뀌었다** — LTN 82.80 · NeSy-SMP 82.79 > BiLSTM 82.14 > XGBoost 81.81. 논문도 F1·정확도에서 NeSy-SMP 가 1등이었다.
4. **그래도 규칙(NeSy-SMP)과 규칙 없음(LTN)은 같다** (AUC 92.27 = 92.27, F1 82.79 vs 82.80). 성능 향상은 규칙이 아니라 **데이터 정제**에서 왔다.
   → 논문 결과와의 차이 중 "XGBoost 가 크게 이긴다"는 부분은 **입력 데이터 품질 문제**로 상당 부분 설명된다. "지식 규칙이 성능을 올린다"는 주장은 여전히 재현되지 않는다.

## 한계
- 유효 범위는 mimic-code 기준 — 논문은 이상치 처리를 적지 않았다(원저자가 따로 처리했는지 알 수 없음).
- 딥러닝 계열은 torch 시드 미고정으로 실행마다 ±0.3 정도 흔들린다(원본 재실행 기준).

## 해석

1. **데이터 정제 효과는 네 시점 모두에서 유지된다.** 딥러닝 계열 +1.1~2.7, 트리 계열 −0.24~+0.08. 실행 편차(±0.1~0.3)보다 크다. 원인도 같다 — 변수별 MinMax 정규화가 기록 오류 최댓값 하나에 끌려간다.
2. **XGBoost 와의 격차가 전 시점에서 줄고, 48h 에서는 뒤집힌다.** AUC 차이 1.4~1.9 → 0.4~0.6, 48h 는 LTN 87.84 · NeSy 87.80 > XGBoost 87.45.
3. **F1 은 네 시점 모두 LTN/NeSy 가 1위다.** 논문도 F1·정확도에서 NeSy-SMP 를 1위로 보고했다 — 방향은 일치하지만, **규칙 없는 LTN 이 같거나 더 높다**는 점이 논문과 다르다.
4. **NeSy-SMP 와 LTN 의 차이는 여전히 없다** (−0.06 ~ +0.07, 실행 편차 이하). 향상은 규칙이 아니라 데이터 정제에서 왔다는 6h 결론이 전 시점에서 확인됐다.

## 한계 (6h 와 동일)

- 유효 범위는 mimic-code 기준이며, 논문은 이상치 처리를 기술하지 않았다.
- torch 시드 미고정 — 딥러닝 계열은 실행마다 ±0.1~0.3 흔들린다. 시점별 1회 실행이다.
