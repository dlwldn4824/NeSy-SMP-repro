## 2. 성능 — 원본 조건 재현과 비교 (6h, 5-fold)

| 모델 | 원본 코드 AUC | 민감도 A AUC | 차이 | 원본 F1 | A F1 |
|---|---:|---:|---:|---:|---:|
| XGBoost | 92.67 ± 0.45 | 92.67 ± 0.45 | 0 (동일 — 규칙 미사용) | 81.72 | 81.72 |
| RF | 91.18 ± 0.65 | 91.18 ± 0.65 | 0 (동일) | 76.75 | 76.75 |
| BiLSTM | 89.71 ± 1.33 | 90.33 ± 1.42 | +0.62 | 80.62 | 80.40 |
| LTN (규칙 없음) | 91.27 ± 0.83 | 91.23 ± 0.71 | −0.04 | 81.74 | 81.86 |
| **NeSy-SMP (규칙 있음)** | 91.02 ± 0.84 | **91.17 ± 0.75** | **+0.15** | 81.66 | 81.56 |

- **규칙 판정을 고쳐도 NeSy-SMP 는 LTN 을 넘지 못한다** (91.17 vs 91.23). fold 별로 NeSy-SMP 가 높은 건 5번 중 2번.
- NeSy-SMP 의 +0.15 는 fold 간 표준편차(0.75~0.84)보다 훨씬 작다. **규칙 오류가 "NeSy 가 최고가 아닌" 이유는 아니다.**
- XGBoost·RF 는 값이 완전히 같다 → 바뀐 것이 공리 조건뿐임을 확인(무작위 고정 확인용).
- BiLSTM·LTN 은 규칙과 무관한데도 ±0.6 움직인다 → **torch 시드 미고정에 따른 실행 간 편차**. 위 +0.15 를 해석하려면 이 편차 크기를 알아야 한다 → §2-1.

## 2-1. 실행 간 편차 — 원본 코드 재실행 (09-18 20:17 완료)

같은 원본 코드·같은 데이터를 기록 패치(P6)만 넣어 다시 돌렸다. XGBoost·RF 는 세 실행 모두 동일.

| 모델 AUC | 원본 1회차 | 원본 2회차 (재실행) | missing-aware | 재실행 편차 (2−1) | missing-aware − 재실행 |
|---|---:|---:|---:|---:|---:|
| BiLSTM | 89.71 | 90.00 | 90.33 | +0.29 | +0.33 |
| LTN | 91.27 | 91.21 | 91.23 | −0.06 | +0.02 |
| **NeSy-SMP** | 91.02 | 91.14 | 91.17 | **+0.12** | **+0.03** |

- fold 별로는 **같은 코드인데도** NeSy-SMP 가 −0.44 ~ +0.73, BiLSTM 이 −2.73 ~ +3.00 움직인다.
- missing-aware 의 NeSy-SMP +0.15 중 **+0.12 는 재실행만으로도 생기는 차이**다. 재실행과 비교하면 +0.03 — **규칙 판정 수정의 성능 효과는 사실상 0.**

## 3-1. Knowledge satisfaction — 원본 vs missing-aware

| | 원본 (재실행) | missing-aware |
|---|---:|---:|
| data 공리 | 0.609 | 0.609 |
| knowledge 공리 | 0.791 | 0.796 |
| activation GCS / SBP / 크레아티닌 / 혈소판 | 100 / 100 / 0 / 9.2% | 27.2 / 71.0 / 27.1 / 3.7% |

- 공리별 satisfaction 도 거의 같다 (차이 0.01 이하, 크레아티닌 앵커는 원본에서 한 번도 켜지지 않아 값 없음).
- 원본에서 GCS·SBP 앵커는 **전원에게** 걸리는데도 satisfaction 이 0.99~1.00 — 위험 술어 MLP 가 "모두 위험"으로 쉽게 맞춘다. 이 앵커들은 사망 함축(`impl:`) 공리에 연결돼 있지 않아 **최종 사망 예측에 영향을 줄 경로가 없다** (호흡수·혈압·GCS·크레아티닌은 앵커만 있고 함축 공리가 없음).
- → 잘못 켜진 규칙이 성능에 영향을 못 준 이유: **그 규칙들은 애초에 사망 예측과 연결돼 있지 않았다.**

## 3. Knowledge satisfaction (민감도 A)

학습 배치 평균, 마지막 epoch · 5 fold 평균: **data 공리 0.609 · knowledge 공리 0.796** (검증 F1 최고 epoch: 0.599 / 0.791)

공리별 satisfaction (낮을수록 모델이 그 규칙을 덜 따름)

| 낮은 쪽 | 값 | | 높은 쪽 | 값 |
|---|---:|---|---|---:|
| 나이 → 사망 함축 | 0.609 | | GCS 앵커 | 1.000 |
| 젖산 안 떨어짐 앵커 | 0.714 | | 크레아티닌 앵커 | 1.000 |
| 젖산 떨어짐(부정) 앵커 | 0.741 | | CRP 앵커 | 0.998 |
| 만성질환 → 사망 함축 | 0.755 | | 호흡수·수축기혈압 앵커 | 0.995 |
| 빌리루빈 → 사망 함축 | 0.775 | | CRP → 사망 함축 | 0.971 |

- **앵커 공리(지표가 임계값을 넘은 환자에게 위험 술어를 참으로)는 거의 1.0** — 쉽게 만족된다.
- **함축 공리(위험 술어 → 사망 예측)가 낮다.** 특히 나이 0.609 · 만성질환 0.755 — 고령·만성질환자 절반 이상이 실제로 생존하므로 "위험하면 사망"을 그대로 만족시킬 수 없다.
- 즉 지식 공리는 **데이터와 충돌하는 방향으로 압력을 준다**. 가중치가 0.2 라 성능을 크게 해치지도, 돕지도 않는 현재 결과와 일관된다.
- 원본과의 비교는 §3-1.
