# CAM 평가 단위 split — 설계안

근거: `17_cam_split_eda.py` (출력 `notes/eda/out_split/*.csv`) · `18_split_supplement.py`
관련 결정 문서: `COHORT_AB_DECISION.md` · `LNN_DESIGN.md`

## 0. 결론 먼저

| 질문 | 답 |
|---|---|
| 예측 단위를 stay → CAM 평가 시점으로 바꿀 만한가 | **그렇다.** instance 가 29,500 → 348,879 로 늘고, 관찰기회 편향의 주원인이 사라진다 |
| 타깃은 '다음 평가 결과'인가 '앞으로 24h 내 P'인가 | **앞으로 24h 고정.** '다음 평가'는 예측 지평이 결과와 같이 움직인다 (§2) |
| UTA 시점도 예측 시점으로 쓰나 | **써야 한다.** 여기가 LNN 이 CBM 을 이기는 유일한 지점인데 현재 EDA 는 통째로 버리고 있다 (§3) |
| train/val/test 를 어떻게 나누나 | **환자 단위 필수.** 기록 단위면 환자의 88.3% 가 양쪽에 걸친다 (§5) |
| 코호트 A안/B안 결정이 아직 필요한가 | **불필요해진다.** 평가 단위로 가면 '이미 섬망'은 제외가 아니라 계층이 된다 (§6) |

## 1. 왜 평가 단위인가 — stay 단위가 재던 것

기존 설계(`LNN_DESIGN.md` §5)는 stay 하나에 라벨 하나였다: 첫 24h 관찰 → 24–72h 창에 P 가 있나.

| | stay 단위 (기존) | 평가 단위 (이 안) |
|---|---:|---:|
| instance | 22,867 (A안) / 29,500 (B안) | **348,879** |
| 라벨 못 붙이는 비율 | 47.9% | 28.3% |
| 관찰기회 편향 | 2.8배 (창 내 평가 횟수 차이) | 구조적으로 없음 |

stay 단위의 "창 안에 P 가 한 번이라도"는 **평가를 많이 받을수록 유리한 지표**였다. 24–72h 고정으로 26배 → 2.8배까지 줄였지만 남아 있었다. 평가 단위에서는 instance 하나가 평가 하나이므로 이 편향이 정의상 사라진다.

**대신 새 편향이 생긴다.** 장기 재원 stay 가 instance 를 많이 낸다 — 상위 10% stay 가 instance 의 40.1%, 최다 stay 하나가 343개. 이건 §7 에서 가중치로 처리한다.

## 2. 타깃 — '다음 평가 결과'를 쓰면 안 되는 이유

직관적으로는 "다음 확정 평가가 P 인가"가 자연스럽고, 실제로 시간 간격도 걱정만큼 넓지 않았다:

```
전이 간격  median 11.0h (IQR 4.0-12.6) · 24h 초과는 8.2% 뿐
```

**문제는 폭이 아니라 방향이다.** 간격이 결과와 같이 움직인다:

| transition | median 간격 | ≤12h |
|---|---:|---:|
| N→N | 9.9h | 71.0% |
| N→P | **12.0h** | 60.6% |
| P→N | 12.0h | 55.7% |
| P→P | 10.0h | 69.0% |

상태가 바뀌는 쪽의 간격이 더 길다. 즉 **"다음 평가가 언제 오는가" 자체가 결과의 정보를 담고 있는데, 예측 시점에서는 그걸 알 수 없다.** 지평이 instance 마다 다르면서 그 차이가 라벨과 상관되면, 성능이 임상적 예측력인지 평가 스케줄 패턴인지 분리되지 않는다.

**→ 고정 24h 창 채택.** 모든 instance 에서 지평이 같다.

| 창 | 라벨 생성률 | 그중 Positive |
|---|---:|---:|
| 앞으로 12h | 60.3% | 27.9% |
| **앞으로 24h** | **80.3%** | **31.2%** |

12h 는 라벨 손실이 너무 크다. 24h 는 손실 19.7% 에 클래스 균형 31.2% 로 둘 다 무난하다.
('다음 평가 결과' 타깃은 민감도 분석으로 같이 돌린다 — 결론이 뒤집히는지만 본다.)

> ⚠️ **탈락분은 무작위가 아니다.** `COHORT_AB_DECISION.md` §3 에서 확인된 것과 같은 구조 — 조기 ICU 퇴실이 주 사유이고 사망은 소수다. 탈락군 구성표를 논문 부록에 넣고, '창 내 확정평가 없음'을 제3의 클래스로 두는 안을 민감도로 함께 본다.

## 3. 🔴 UTA 시점을 예측 시점에서 빼면 안 된다

`17_cam_split_eda.py` 는 `conf = cam[cam.v != "U"]` 로 시작한다. **UTA 를 타깃에서 빼는 건 맞지만, 예측 시점(앵커)에서까지 뺐다.** 이건 이 프로젝트의 핵심 주장을 스스로 지우는 것이다.

앵커를 모든 CAM 기록으로 열고 타깃만 확정(P/N)으로 두면 (`18_split_supplement.py`, 240h 캡 적용):

| 앵커 상태 | 앵커 수 | 라벨 생성률 | 24h 내 Positive |
|---|---:|---:|---:|
| Negative | 293,665 | 78.8% | **12.2%** |
| **UTA** | 103,202 | **41.8%** | **53.5%** |
| Positive | 89,477 | 83.1% | **78.8%** |

두 가지가 동시에 보인다.

**(1) UTA 는 N 과 P 사이에 있다.** 12.2% → 53.5% → 78.8%. `LNN_DESIGN.md` §2 가 전이 데이터에서 보인 8.6 / 45.6 / 71.4 패턴이 고정 24h 창이라는 **다른 타깃 정의에서도 그대로 재현됐다.** UTA 를 `[0,1]`(완전 무지)로 두는 건 정보를 버리는 것이라는 주장에 독립적인 근거가 하나 더 생겼다.

**(2) UTA 앵커는 라벨 생성률이 절반 이하다** (41.8% vs 78.8 / 83.1%). 깊이 진정된 환자는 24h 뒤에도 여전히 평가 불가라는 뜻이다. **이 탈락 자체가 `Assessable` 술어의 실체**이고, 결측이 아니라 가이드라인 이탈(PADIS D-01)이라는 프레이밍의 데이터 근거가 된다.

규모:

```
확정(P/N) 앵커만              305,712 instance / 51,390 stay
+ UTA 앵커                    +43,167 (14.1% 증가)
UTA 앵커 덕에 살아남는 stay    2,163
```

14.1% 증가 자체는 크지 않다. **중요한 건 이 43,167개가 CBM 과 LNN 이 갈리는 유일한 지점이라는 것이다** — 현재 상태가 관측 불가인 시점에서 점값을 강제할 것이냐, 구간으로 남길 것이냐. 이걸 빼면 두 모델의 차이를 보여줄 데이터가 없다.

## 4. 🔴 이전 상태가 너무 강하다 — 평가 설계에 반영해야

| 이전 확정 상태 | 다음이 Positive |
|---|---:|
| Negative | 9.5% |
| Positive | **71.3%** |

**"직전 상태를 그대로 이월"하는 무학습 baseline 이 이미 상당한 성능을 낸다.** 전체 AUC 하나로 보고하면 모델이 아니라 이 한 변수를 보고 있는 것이고, 리뷰어가 가장 먼저 찌를 지점이다.

**→ 계층별 보고를 주 결과로 한다.**

| 계층 | instance | Positive | 이 계층에서 묻는 것 |
|---|---:|---:|---|
| 앵커 = N | 231,330 | 12.2% | **신규 발생 예측** ← 임상적으로 가장 유용 |
| 앵커 = P | 74,382 | 78.8% | 지속 vs 회복 |
| 앵커 = U | 43,167 | 53.5% | **관측 불가 상태에서의 예측** ← LNN 차별점 |

전체 지표는 참고로만 두고, **주 지표는 앵커=N 계층의 성능**으로 잡는다. 여기가 carry-forward baseline 이 가장 약한(기저 12.2%) 구간이면서 "새로 생길 사람을 미리 잡는다"는 임상 주장에 직접 대응한다. carry-forward baseline 은 전 계층에서 반드시 같이 보고한다.

## 5. train / val / test 분할

**환자 단위 분할이 선택이 아니라 필수다.**

```
instance 2개 이상인 환자   88.3%   → 기록 단위 분할은 대부분의 환자가 양쪽에 걸린다
stay 2개 이상인 환자       21.9%   → stay 단위 분할도 새지 않는다고 말할 수 없다
```

권장 분할 (240h 캡 + UTA 앵커 포함 기준):

| | 환자 | instance |
|---|---:|---:|
| train 70% | ~28,064 | ~244,215 |
| val 15% | ~6,013 | ~52,331 |
| test 15% | ~6,013 | ~52,331 |
| **계** | **40,092** | **348,879** |

**층화 기준**: 환자당 instance 수가 균등하지 않으므로(상위 10% 환자가 37.3%) 환자 수만 맞추면 instance 수가 흔들린다. `(Positive 경험 여부, instance 수 구간)` 2축으로 층화한다. Positive 를 한 번이라도 겪은 환자는 37.4%.

**추가로 시간 기반 외부검증 하나.** era 가 이 프로젝트의 알려진 교란 요인이므로(`chk_B_era.csv`), 2011–2016 학습 / 2017–2019 평가를 별도 test 로 둔다. 랜덤 분할 성능과의 격차가 곧 일반화 주장의 근거다.

## 6. 코호트 제한 — 그리고 A안/B안이 사라지는 이유

`17_` CELL 9 결과:

| 코호트 | stays | instance | 타깃 Positive% |
|---|---:|---:|---:|
| 성인 + LOS≥1d | 74,829 | 394,879 | 26.5% |
| + 환자당 첫 stay | 51,838 | 253,817 | 26.2% |
| + 2011–2019 | 42,895 | 279,041 | 26.2% |
| + 첫 stay + 2011–2019 | 31,043 | 190,698 | 25.8% |
| + MICU 계열 | 9,476 | 68,997 | 35.1% |

**권장: 성인 + LOS≥1d 만 걸고 나머지는 필터가 아니라 공변량으로 둔다.**

- **첫 stay 제한 불필요.** 이 제한의 목적은 환자 내 상관 제거인데, 그건 §5 의 환자 단위 분할이 이미 해결한다. instance 를 36% 버릴 이유가 없다. (단 `COHORT_AB_DECISION.md` 의 base3 는 첫 stay 를 포함하므로, **이건 기존 합의를 바꾸는 것이라 랩미팅 확인이 필요하다.** 첫 stay 한정은 민감도 분석으로 유지.)
- **era 는 필터 대신 공변량 + §5 의 시간 분할**로 다룬다.
- **MICU 한정은 반대.** n 이 1/4 로 줄고 Positive% 가 26.5 → 35.1% 로 뛴다. 케이스믹스가 다른 집단이므로 주 분석으로 쓰면 결론의 일반화가 막힌다.

### A안 / B안 결정이 필요 없어진다

`COHORT_AB_DECISION.md` 의 쟁점은 "첫 24h 에 이미 CAM Positive 인 7,985명을 뺄 것인가"였다. **평가 단위로 가면 이 사람들은 제외 대상이 아니라 `앵커 = P` 계층(74,382 instance)이 된다.** 제외/포함을 고를 필요 없이 둘 다 보고된다.

같은 논리로 `17_` CELL 8 이 지적한 P→N→P 도 별도 코호트가 아니다 — "이전 이력에 P 와 N 이 모두 있는 앵커"로 자동 포함된다. (참고 규모: 엄격 정의 5,772 stay = Positive 경험 stay 의 27.7%, 회복 → 재발 median 15.2h, 24h 이내 재발 64.4%.)

**→ 랩미팅에 A/B 결정을 요청하는 대신, "평가 단위로 전환하면 이 결정이 불필요해진다"를 안건으로 올린다.**

## 7. 장기 재원 stay 지배 문제

Positive 율이 재원 시간에 따라 단조 증가한다 (`17_` CELL 7):

| 입실 후 | instance 비중 | Positive% |
|---|---:|---:|
| 0–24h | 18.3% | 16.0% |
| 24–48h | 19.6% | 17.8% |
| 48–72h | 12.7% | 23.3% |
| 72–120h | 15.0% | 28.1% |
| 120–240h | 16.9% | 35.8% |
| 240h+ | 17.5% | **39.2%** |

장기 재원 = 더 아픔 = instance 도 많고 Positive 율도 높다. 삼중으로 겹친다.

**대응 3종:**

1. **240h(10일) 캡.** instance 의 17.5% 를 잘라내면서 집중도가 크게 완화된다. §3–§5 의 숫자는 모두 캡 적용 후 값이다.
2. **stay 당 instance 상한.** cap=20 이면 348,879 → 335,052 (−4.0%) 로 2,263 stay 만 영향받는다. cap=10 은 −20% 로 비용이 크다. **cap=20 권장**, 또는 손실에서 stay 당 가중치 `1/n_instance`.
3. **입실 후 경과시간을 명시적 피처로** 넣고, 성능을 시간 구간별로 층화 보고한다.

## 8. 최종 설계 요약

```
예측 단위   CAM 기록 1건 = instance 1개 (P / N / UTA 모두 앵커)
코호트      성인 + ICU LOS >= 24h, 모든 stay 포함 (첫 stay 제한 없음)
관찰창      앵커 시점까지의 모든 기록 (좌측 전체)
타깃        앵커 이후 24h 안에 확정 CAM Positive >= 1
라벨 제외   24h 창 안에 확정 평가가 없는 앵커 (28.3%) — 구성표 부록
시간 캡     입실 후 240h 까지, stay 당 instance cap 20
분할        환자 단위 70/15/15, (Positive 경험 × instance 수) 층화
            + 2011-2016 학습 / 2017-2019 평가 시간 분할 별도

규모        instance 348,879 · stay 51,390+ · 환자 40,092 · Positive 31.5%
계층        앵커 N 231,330 (12.2%) · P 74,382 (78.8%) · U 43,167 (53.5%)
주 지표     앵커=N 계층 성능 (신규 발생) — carry-forward baseline 대비
```

## 9. 확정 전에 남은 것

1. **`17_` 를 UTA 앵커 포함으로 고쳐 다시 돌린다.** 현재 `conf` 필터가 §3 의 근거를 지운다. (`18_split_supplement.py` 가 임시로 채웠으나 본 스크립트에 반영 필요)
2. **carry-forward baseline 을 먼저 측정한다.** 이 숫자가 나오기 전에는 어떤 모델 성능도 해석할 수 없다. 며칠이면 된다.
3. **첫 stay 제한 해제**는 `COHORT_AB_DECISION.md` 의 base3 를 바꾸는 것이라 랩미팅 확인.
4. **`LNN_DESIGN.md` §4 의 LTN ablation 4종은 이 설계와 독립**이다. 먼저 시작해도 된다 — 평가 단위로 바뀌어도 UTA 표현 문제는 동일하다.

> ⚠️ 이 전환의 대가를 명시해 둔다. 평가 단위는 **"이 환자가 섬망에 걸릴까"가 아니라 "지금 이 시점에서 24h 안에 섬망 판정이 나올까"를 예측한다.** 후자가 임상 배치에는 더 맞지만(매 평가마다 돌아가는 모델), 원 논문과의 직접 비교는 불가능해진다. 원 논문 재현 표는 stay 단위로 따로 유지해야 한다.
