## 1. split 방식 — 한 환자를 어떻게 쪼개나

### 그림

```
한 stay 의 CAM 기록 시계열 (시간 →)

  입실                                                              240h 캡
   │                                                                  │
   ▼                                                                  ▼
   ├──●────────●─────────●──────────●─────────●──────────●────────────┤
      U        N         P          U         P          N
      │        │         │          │         │          │
   각 CAM 기록 하나가 = 앵커 하나 = instance 하나 (UTA 포함)


앵커 하나를 확대하면:

        ←──── X (입력) ────┤ 앵커 ├──── y (타깃) ────→
                           │  t   │
   ┌───────────────────────┤      ├──────────────────┐
   │ 시계열: 이전 24h       │      │ 이후 24h 안에     │
   │   RASS / 진정제        │      │ 확정 CAM(P/N) 중  │
   │   mobility / pain      │      │ Positive 가       │
   │ 누적: 입실~t 요약      │      │ 한 번이라도 있나  │
   │   uta_frac, n_assess   │      │                   │
   │   경과시간, 직전 확정상태│     │  → y ∈ {0, 1}     │
   │ 정적: age, careunit    │      │  창 안에 확정평가 │
   └───────────────────────┘      │  없으면 instance  │
                                  │  제외 (29.0%)     │
                                  └──────────────────┘
   ※ 앵커 시점의 CAM 값 자체는 X 에 들어간다 (직전 상태로).
     y 는 앵커 "이후" 만 본다 — 누수 없음.
```

### 실제 환자 전개 (`stay_id=35018056`, 앵커 11개: 확정 7 / UTA 4)

| 입실후 | CAM | X = 이 시점까지 | y = 이후 24h 내 P |
|---:|:--:|---|---|
| 0.4h | U | 0 ~ 0.4h | **0** (14.6h N 이 창 안, P 없음) |
| 10.7h | U | 0 ~ 10.7h | **0** |
| 14.6h | N | 0 ~ 14.6h | — 제외 (다음 확정이 38.6h, 창 밖) |
| 38.6h | P | 0 ~ 38.6h | — 제외 |
| 62.6h | U | 0 ~ 62.6h | — 제외 |
| 86.6h | U | 0 ~ 86.6h | **1** (98.9h P 가 창 안) |
| 98.9h | P | 0 ~ 98.9h | — 제외 |
| 134.6h | N | 0 ~ 134.6h | — 제외 |
| 169.7h | P | 0 ~ 169.7h | **0** (182.6h N 이 창 안) |
| 182.6h | N | 0 ~ 182.6h | — 제외 |
| 231.5h | N | 0 ~ 231.5h | — 제외 |

**→ stay 1개 = 앵커 11개 = instance 4개** (7개는 창 안에 확정평가가 없어 탈락)

이 환자가 설계의 세 가지를 한 번에 보여준다.
- UTA 앵커(86.6h)가 **y=1 을 만든다** — 예측 시점의 상태가 관측 불가여도 예측 대상은 된다
- 평가 간격이 벌어지면(24h 초과) 탈락한다 — 이 환자는 후반부 간격이 넓어 7/11 이 날아갔다
- P→N→P(38.6 → 134.6 → 169.7)가 별도 처리 없이 그냥 포함된다

> 이 환자는 탈락률이 유난히 높은 편이다(64%). 전체 평균은 29.0% 다.

## 2. split 후 표본 수

### 2-a. transition 4종 (연속한 확정 P/N 쌍)

| transition | 건수 | stay | **환자** | 건수% | 간격 median |
|---|---:|---:|---:|---:|---:|
| N→N | 224,432 | 46,542 | 35,470 | 68.9% | 9.4h |
| **N→P** | **20,417** | **12,989** | **11,161** | 6.3% | 11.8h |
| P→N | 23,900 | 15,837 | 13,369 | 7.3% | 12.0h |
| P→P | 57,194 | 12,784 | 10,864 | 17.5% | 8.5h |
| **합계** | **325,943** | **52,709** | **39,251** | | |

**N→P(신규 발생)가 20,417건 / 11,161명.** 주 지표 계층으로 쓰기에 모수는 충분하다.

### 2-b. 고정 24h 타깃 (권장 정의) — 앵커 상태별

| 앵커 | 앵커 수 | 라벨 생성 | 생성% | y=1 | Positive% | stay | 환자 |
|---|---:|---:|---:|---:|---:|---:|---:|
| N | 293,665 | 229,601 | 78.2% | 27,696 | **12.1%** | 47,971 | 36,322 |
| P | 89,477 | 73,234 | 81.8% | 57,595 | **78.6%** | 17,793 | 14,764 |
| U | 103,202 | 42,670 | 41.3% | 22,768 | **53.4%** | 18,563 | 16,625 |
| **합계** | **486,344** | **345,505** | **71.0%** | 108,059 | **31.3%** | **53,519** | **40,070** |

### 2-c. 직전 확정상태 × 현재 앵커 (교차표)

Positive% — 셀 안의 수는 instance 수:

| 직전 확정 \ 현재 앵커 | N | P | U |
|---|---|---|---|
| **(없음, 첫 평가)** | 10.9% (38,166) | 69.4% (9,551) | 42.7% (20,176) |
| **N** | 8.9% (172,513) | 65.0% (16,112) | 44.8% (10,359) |
| **P** | 43.4% (18,922) | 85.1% (47,571) | **78.3%** (12,135) |

읽는 법 두 가지.

1. **현재 앵커만으로 부족하다.** 앵커=N 이라도 직전이 P 였으면 43.4%, 직전이 N 이면 8.9% — 5배 차이다. 이력이 반드시 입력에 들어가야 한다.
2. **UTA 의 의미가 이력에 따라 완전히 달라진다.** 42.7% → 44.8% → **78.3%**. UTA 를 단일 진리값으로 두면 안 된다는 §6 의 근거다.

## 3. 모델 입력 / 출력

### 출력

```
주 타깃   y = 1  if  앵커 t 이후 (t, t+24h] 안에 CAM = Positive 가 1건 이상
              0  if  창 안에 확정 CAM(P/N) 은 있으나 Positive 는 없음
              —  창 안에 확정 CAM 이 없으면 instance 에서 제외 (29.0%)

보조 (개념층, LNN_DESIGN §6 의 concept bottleneck)
  DeepSedation(t)  = 이전 24h 에 RASS <= -4        기저 18.0%
  Assessable(t)    = 창 안에 확정 CAM 이 있나       기저 71.0%   ← 위의 '제외' 를 라벨로 재활용
```

`Assessable` 을 보조 출력으로 두면 **제외한 29.0% 가 버려지지 않는다.** 그 instance 는 `Assessable=0` 의 양성 예시가 된다.

### 입력 — 커버리지 확인 결과

앵커 시점 이전 구간에 실제로 뭐가 있는지 재봤다 (라벨 생성된 345,505 instance 기준):

| 입력 | instance 커버 | median 측정 수 |
|---|---:|---:|
| RASS (이전 6h) | 99.8% | 2 |
| **RASS (이전 12h)** | **100.0%** | 3 |
| **RASS (이전 24h)** | **100.0%** | 5 |
| RASS ≤ −4 있음 (이전 24h) | 18.0% | — |
| 진정제 주입 (이전 24h) | 35.6% | — |
| └ 그중 benzodiazepine | 11.1% | — |
| 이전 CAM 기록 ≥ 1건 | 86.2% | 4 |

**lookback 24h 로 확정한다.** RASS 가 100% 커버되고 median 5회면 시계열로 충분하다. 6h 로 줄이면 median 2회라 얇다.

이전 CAM 이 없는 13.8% 는 첫 평가 시점 앵커다 — `prev_conf = (없음)` 으로 명시 인코딩한다 (§2-c 첫 행).

### 입력 구성 (확정)

```
[시계열] 앵커 이전 24h, 등간격 리샘플
   RASS                      커버 100%
   진정제 주입 여부/용량      propofol · dexmed · benzo 3계열
   mobility · pain NRS · GCS  ⚠️ 아래 참조
   활력징후

[누적] 입실 ~ 앵커
   경과시간 (입실 후 h)          ← Positive% 가 16%→39% 로 단조 증가. 필수
   n_assess, uta_frac
   직전 확정 상태 {N, P, 없음}   ← §2-c. 단일 변수로 가장 강하다
   누적 benzo 노출

[정적] age · gender · first_careunit · anchor_year_group · ED 경유
```

|---|---:|

| PAIN_NRS | 96.2% |

`eda/24_extract_mobility_pain_gcs.py` 로 뽑았다 (chartevents 풀스캔 74초, 10.3M 행 → `_extra_values.parquet` 51MB).
`00_extract.py` 의 `VALUE_IDS` 도 넓혀 뒀으니 다음 전체 재추출부터는 자동 포함된다.

**다만 itemid 별로 척도가 섞여 있어 그대로 쓰면 안 된다.** 확인 후 고른 것만 쓴다:

| 항목 | 쓰는 itemid | 척도 | 커버 | 버린 것 |
|---|---|---|---:|---|

| Mobility | 224057 · 229321 | Braden 1–4 / JH-HLM 1–8 | 99.9% / 55% | 229633(값 16–57, 다른 측정) · 228697 · 229319 · 229742 (표본 과소) |

PAIN 은 `valuenum` 이 43.7% 만 차 있는데, 비어 있는 대부분이 `Unable to Score` 다 — **통증에서도 '평가 불가'가 구조적으로 존재한다.** CAM 의 UTA 와 같은 성격이라 별도 플래그로 유지한다.

RESTRAINT(50.1%)와 CPOT(19.6%)는 결측이 커서 주 입력으로는 여전히 부적합하다.

## 4. B안 (P→N→P) 모수

확정 CAM 을 가진 57,199 stay / 42,381 환자에서, 연속 중복을 압축한 상태열(`NNPPN` → `NPN`) 기준:

| 패턴 | stay | **환자** | 전체 환자 대비 |
|---|---:|---:|---:|
| 변화 없음 | 39,401 | 31,751 | 72.1% |
| └ N 만 | 36,648 | 29,636 | 67.3% |
| └ P 만 | 2,753 | 2,628 | 6.0% |
| N→P 있음 (신규 발생) | 12,989 | 11,161 | 25.4% |
| P→N 있음 (회복) | 15,837 | 13,369 | 30.4% |
| **★ P→N→P (재발)** | **7,449** | **6,655** | **15.1%** |
| └ P→N→P→N | 5,245 | 4,824 | 11.0% |
| └ P→N→P→N→P | 2,787 | 2,629 | 6.0% |

상위 패턴: `N` 64.1% · `PN` 8.4% · `NPN` 6.3% · `P` 4.8% · `NP` 3.4% · `PNPN` 2.4% · `PNP` 2.3%

### 판정

**모수는 충분하다 — 6,655명.** 하지만 **별도 코호트로 뽑을 이유가 없다.**

P→N→P stay 를 평가 단위로 풀면 **instance 100,728개 (전체의 29.2%), Positive 67.0%** 다. A안 안에 이미 3분의 1 가까이 들어 있고, "이전 이력에 P 와 N 이 모두 있는 앵커"라는 조건으로 언제든 잘라낼 수 있다.

> ⚠️ `17_` 의 "엄격 P,N,P 연속 3개 = 5,772 stay" 와 여기 7,449 stay 는 정의가 다르다. `17_` 은 확정 평가 **3개가 정확히** P,N,P, 여기는 압축열에 `PNP` 포함(= `PP N PP` 도 셈). 둘 다 맞고 후자가 임상적 재발 정의에 가깝다.

**→ B안은 "가능한가"가 아니라 "A안의 하위 분석으로 충분한가"의 문제이고, 답은 충분하다.**

### 🔴 남은 블로커 — LTN 소비 경로

`delirium_kg.py` 가 rdflib 쪽에 술어 3개(`decreasesRiskOf` / `hasNoEffectOn` / `precludes`)를 정의했지만,
**LTN 파이프라인은 아직 이 셋을 모른다.** 각각 컴파일 방식이 다르다:

| 술어 | 컴파일 | 고칠 곳 |
|---|---|---|
| `decreasesRiskOf` | 함축 머리에 부정 — `∀x Pred(x) → ¬Delirium(x)` | `pipeline/horn_to_ltn.py` |
| `hasNoEffectOn` | 공리 아님. **마이닝 규칙 기각 필터** | `filter_rules.py` |
| `precludes` | `Assessable` 가드 | `horn_to_ltn.py` + 개념층 |
| 전부 | 어휘 등록 | `configs/relation_vocab.json` |

> 상대 문서 §4 가 지적한 대로, 음의 방향 공리가 없으면 술어가 전부 양의 방향으로 쏠려
> **원 논문 Table 3 의 LTN-AK collapse** 가 재현될 수 있다. 이건 M4 의 실질 리스크다.

### 그 외 주의

- **`PADIS-G-01`(precludes) 만 출처가 PADIS 가 아니다** — 우리 데이터 관측(UTA 의 78.1% 가 RASS ≤ −4)이다. 논문에서 가이드라인 공리와 섞으면 안 된다.
- **깊은 진정의 시점 분리** (상대 문서 §5): 위험 공리는 앵커 *이전* lookback 에, 평가 불능 가드는 앵커 *현재* 에. 우리 split 설계가 이미 이렇게 나뉘어 있다 — §3 의 lookback / 앵커 구분이 그대로 대응한다.
- **`padis_rules_approved.json` 은 건드리지 않았다** — 사람이 `approve_rules.py` 로 승인한 결과여야 하는 파일이다.
- `padis/kg/delirium_kg.py` 는 현재 **실행되지 않는다** — `from utils import visualize` 가 `NeSy-SMP/utils.py` 를 못 찾고, `pyvis` 도 venv 에 없다. 그래프 구성 로직 자체는 정상이다.

## 6. UTA 역할 재정리

### 바뀐 것

`LNN_DESIGN.md` 는 stay 단위 설계였고, 거기서 `Delirium(x)` 은 **출력**이었다. UTA 시점에 출력 진리값을 뭘 줄지가 문제였고 — 0.5도 masking도 0도 다 틀렸으니 구간 `[L,U]` 가 필요하다는 게 LNN 정당화였다.

**평가 단위로 오면 UTA 는 출력에서 완전히 빠진다.** 타깃은 확정 P/N 만 본다. 억지 진리값을 줄 일이 없다.

### 대신 UTA 가 갖는 세 역할

| 역할 | 정의 | 규모 |
|---|---|---|
| **① 앵커** | UTA 시점도 예측 시점이 된다 | 앵커 103,202 → instance **42,670** (14.1% 증가) |
| **② 입력** | 앵커 이전의 UTA 이력 (uta_frac, 연속 UTA 길이, 직전 확정상태) | 전 instance |
| **③ 검열** | 창 안에 확정평가가 없어 탈락 | UTA 앵커의 **58.7%** 가 여기 (N/P 앵커는 ~20%). 그중 **84.2% 는 '전부 UTA'** — 진정이 이어진 것이다 (`21_`) |

③ 이 핵심이다. UTA 앵커는 라벨 생성률이 41.3% 로 N(78.2%)·P(81.8%)의 **절반**이다. 깊게 진정된 환자는 24h 뒤에도 여전히 평가 불가라는 뜻이고, 이건 결측이 아니라 **`Assessable` 이라는 관측 가능한 현상**이다. §3 처럼 보조 출력으로 두면 버려지지 않는다.

### UTA 는 단일 진리값이 될 수 없다 (§2-c 재확인)

| UTA 앵커의 직전 확정 상태 | 24h 내 Positive |
|---|---:|
| (없음) | 42.7% |
| N | 44.8% |
| P | **78.3%** |

**같은 "UTA" 인데 42.7% ~ 78.3% 로 벌어진다.** 하나의 값(0.5든, 0.456이든)으로 못 놓는다. 이력을 조건으로 구간을 좁혀야 하고, 이게 `LNN_DESIGN.md` §2 의 "구간을 데이터로 좁히는 것이 기여"에 정확히 대응한다.

### 🔴 LNN 정당화가 어디로 이동하는지

정직하게 적어 둔다. **원래 논거("UTA 출력에 줄 값이 없다")는 평가 단위에서 사라진다.** 논거가 없어지는 게 아니라 **옮겨간다**:

```
기존 (stay 단위)   UTA 평가 1건의 Delirium 진리값을 뭘로?
                   → 개별 UTA 기록마다 [L,U]

이후 (평가 단위)   24h 창이 '전부 UTA' 인 앵커(60,537 · 전체의 12.4%)의 y 를 뭘로?
                   → 창 단위로 [L,U]
```

대상이 **개별 UTA 기록 → 라벨 미생성 창**으로 바뀐다.

**그런데 `21_` 이 이걸 더 좁혔다.** 라벨 미생성 29.0% 를 원인별로 쪼개니, 구간 진리값이 필요한 것은 **'전부 UTA' 60,537건(전체 앵커의 12.4%, 미관찰의 43.0%)** 뿐이다 — 평가는 했는데 결과가 확정이 아닌 창. 나머지는 ICU 퇴실(32.8%)·사망(2.5%) 같은 **경쟁위험**과 순수 미평가(18.5%)라 구간 문제가 아니고 따로 다뤄야 한다.

이 분리가 중요한 이유는 **두 집단의 방향이 정반대**라서다 — '전부 UTA' 군의 stay 사망률은 **36.1%**, 'ICU 퇴실' 군은 **4.1%** 다(라벨 생성군 10.3%). 통째로 masking 하면 가장 위중한 집단과 가장 건강한 집단을 한꺼번에 버린다. **논거의 구조는 그대로이고, 대상만 또렷해졌다.**

### → `LNN_DESIGN.md` §4 의 ablation 4종을 갈아야 한다

기존 설정 B(`Delirium=0.5`)·C(`Delirium=0`)는 UTA 가 출력일 때만 의미가 있다. 평가 단위용으로:

| 설정 | 처리 | 확인하는 것 |
|---|---|---|
| A | UTA 앵커 제외, 라벨 미생성 창 제외 | 기준선 (가장 흔한 설계) |
| B | UTA 앵커 포함 (입력으로만) | ①② 의 값 — instance +14.1% |
| C | 라벨 미생성 창을 제3 클래스로 (3-way) | ③ 을 명시 라벨로 |
| D | 라벨 미생성 창을 `[L,U]` 구간 제약으로 | **LNN** |

A→B 가 크면 UTA 를 앵커로 살린 것이 옳다. C→D 가 크면 구간 표현이 실제로 필요하다. **C 와 D 가 비슷하면 LNN 은 과잉이고 3-way CBM 으로 충분하다** — 이 판정을 미리 못 박아 둔다.
